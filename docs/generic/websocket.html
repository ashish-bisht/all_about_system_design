02 / Key Concepts
Core Concepts
HTTP 101 kyun? 200 kyun nahi? Hot +
200 OK ka matlab — "response complete, connection band karo." 101 Switching Protocols ek informational code hai (1xx) jiska matlab hai "protocol change ho raha hai, connection khuli rakho." WebSocket ke liye connection open rehni chahiye — isliye sirf 101 kaam karta hai.
Sec-WebSocket-Key ka kya kaam hai? Common +
Client ek random base64 key bhejta hai. Server us key ko ek fixed magic string se jodke SHA1 hash banata hai aur wapas bhejta hai. Iska purpose — verify karna ki server genuinely WebSocket samajhta hai, koi random HTTP server accidentally accept na kar le. Yeh security nahi, protocol verification hai.
WebSocket aur HTTP polling mein fark? Hot +
Polling mein client bar bar server se poochta hai — "koi naya data?" — 99% requests mein jawab hota hai "nahi." Wasteful aur slow. WebSocket mein ek baar connection khulta hai, server khud data push karta hai jab ready ho. Lower latency, much less overhead.
WebSocket vs SSE — kab kaunsa? Common +
SSE (Server-Sent Events) sirf server → client one-way stream hai. WebSocket fully bi-directional hai. Live notifications, news feed, progress bars ke liye SSE enough hai — simpler bhi hai. Chat, games, collaborative editing ke liye WebSocket chahiye kyunki client bhi push karta hai.
Connection close kaise hoti hai? Deep +
WebSocket ka apna close handshake hota hai — TCP jaisa. Koi bhi side ek Close frame bhejta hai with a status code aur reason. Doosri side Close frame se acknowledge karti hai. Phir TCP connection band hoti hai. Abrupt disconnect (network gaya) mein sirf TCP RST aata hai — isliye heartbeat/ping-pong important hai dead connections detect karne ke liye.
WebSocket ka HTTP version dependency? Deep +
Standard WebSocket sirf HTTP/1.1 pe kaam karta hai — Upgrade header HTTP/1.1 ka feature hai. HTTP/2 mein WebSocket ka equivalent alag tarike se handle hota hai (RFC 8441). Real world mein browser to CDN HTTP/2 hota hai, CDN to backend HTTP/1.1 — isliye practically WebSocket HTTP/1.1 upgrade pe hi milega.
Authentication WebSocket mein kaise karein? Hot +
WebSocket handshake mein custom headers nahi bheje ja sakte browser se (limitation hai). Do options: (1) Initial HTTP upgrade request mein query param mein token bhejo — ws://host/ws?token=xyz — server validate kare connect pe. (2) Connect hone ke baad pehla message hi auth token bhejo — server validate kare warna disconnect kare. Option 1 zyada common hai.

04 / Performance
Bottleneck Order — Kya Pehle Toot ta Hai
File Descriptors (OS limit) Default: 1024 / Tuned: 1M+
Pehla wall. ulimit -n se fix hota hai. Har connection = 1 FD.
RAM ~2-8 KB per connection
10K conn ≈ 80 MB. 100K conn ≈ 800 MB. Ek server ka real limit.
Network / Bandwidth Messages per second
High-frequency updates (trading, games) mein bottleneck ban sakta hai.
CPU ~0.1% for 500 idle conns
Async ki wajah se CPU LAST toot ta hai. await = CPU free hai baaki ke liye.

02

Problem: Multiple Servers

User A — Server 1 pe connected. User B — Server 2 pe connected. A ka message B ko kaise milega? Dono servers ek doosre ko jaante hi nahi!

This is the core interview problem
03

Solution: Redis Pub/Sub

Har server Redis ko subscribe karta hai. Koi bhi server message receive kare, Redis pe publish karo. Sab servers ko milega, wo apne connected clients ko bhej denge.

Redis = message broker between servers
04

Load Balancer: Sticky Sessions

Normal load balancer har request pe alag server pe jaata hai — WebSocket ke liye problem! Ek baar connected, same server pe rehna chahiye. Sticky sessions (IP hash) se solve hota hai.

Nginx: ip_hash directive
06 / Watch Out
Common Mistakes + Interview Traps
⚠️ Trap
WebSocket har jagah use karna
REST API, login, file upload — sab ke liye WebSocket use karna overkill hai. Simple request-response ke liye HTTP hi best hai.
⚠️ Trap
Dead connections track nahi karna
Network abruptly gayi — server ko pata nahi chalta. Ping/Pong heartbeat nahi rakha toh RAM mein "ghost connections" bhar jaayenge.
⚠️ Trap
Broadcast loop mein error handling nahi
Ek broken connection pe send fail hua toh poora broadcast loop crash. Try/except har send ke around zaroori hai.
⚠️ Trap
Auth ignore karna
WebSocket endpoint pe koi bhi connect kar sakta hai bina auth ke. Token validation connect ke time pe zaroori hai.
✅ Tip
JSON protocol design pehle karo
Plain text se shuru mat karo. Type field wala JSON protocol pehle design karo — typing indicators, read receipts sab is pe build hote hain.
✅ Tip
Reconnection client side pe rakho
Exponential backoff se auto-reconnect rakho browser mein. Server restart ya deploy hone pe users automatically reconnect ho jayein.
